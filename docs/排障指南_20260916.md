**日期：** 2026-09-17

## 先跑这一条：数据层诊断

**看不到小节时，第一件事是把 TUI 排除在外。** 插件分成两层：`usage.ts`（纯逻辑，无 TUI 依赖）和 `tui.tsx`（渲染）。第一层可以脱离 opencode 单独跑，所以一条命令就能告诉你问题在数据层还是渲染层。

```bash
cat > /tmp/ocgo-diag.ts <<'EOF'
const repo = process.env.REPO
if (!repo) { console.error("请先 export REPO=<仓库绝对路径>"); process.exit(2) }
const { defaultStateDir, resolveKey, fetchUsage, ROWS, formatBar, formatPercent, formatCountdown } =
  await import(`${repo}/usage.ts`)

const dir = defaultStateDir()
const key = resolveKey(dir)
console.log("stateDir:", dir)
console.log("key:", key ? `found (len=${key.length})` : "NOT FOUND")
if (!key) process.exit(1)

const snap = await fetchUsage(key)
console.log("snapshot.kind:", snap.kind)
if (snap.kind !== "ok") {
  console.log("message:", snap.message)
  process.exit(1)
}
for (const row of ROWS) {
  const w = snap.usage[row.key]
  console.log(`${row.label.padEnd(6)} ${formatPercent(w.percent, w.status)} ${formatBar(w.percent)} ${formatCountdown(w.resetsAt)}`)
}
EOF

REPO="$HOME/workspace/opencode-go-usage" bun run /tmp/ocgo-diag.ts
```

仓库不在那个位置就改 `REPO` 的值。脚本本身不含任何硬编码路径，可以原样复制。

> 脚本用 `defaultStateDir()`（opencode 的 data 目录，`auth.json` 真实位置）。V2 没有 `api.state.path.state`，插件也只读这个目录，所以两边结论一致。

一切正常时的输出（数字会不同）：

```
stateDir: /Users/你/.local/share/opencode
key: found (len=67)
snapshot.kind: ok
滚动     1% ░░░░░░░░░░░░░░ 重置于 1 小时 46 分钟
本周    55% ████████░░░░░░ 重置于 4 天 12 小时
本月    27% ████░░░░░░░░░░ 重置于 27 天 20 小时
```

怎么读这个输出：

| 输出 | 含义 | 去哪 |
|---|---|---|
| `key: NOT FOUND` | 密钥解析失败 | [§1.2](#12-没有密钥) |
| `snapshot.kind: dead` | 无 Go 套餐或密钥失效 | [§1.3](#13-无-go-套餐或密钥失效) |
| `snapshot.kind: soft-error` | 网络或上游问题 | [§3](#3-标题带感叹号) |
| 三行都正常打出来了 | **数据层完好，问题在渲染层或插件加载** | [§1.1](#11-插件没加载) |

最后一种情况最常见：数据层没问题，插件根本没被 opencode 加载。

## 1. 侧栏完全没有 `OpenCode Go` 小节

按下面顺序排查。上面那条诊断命令已经把 1.2 和 1.3 区分开了；如果它三行正常，直接看 1.1。

### 1.1 插件没加载

这是最常见的原因，而且有三种具体形态。

**检查注册文件存在且内容正确：**

```bash
cat ~/.config/opencode/cli.json
```

期望输出：

```jsonc
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "plugins": ["/绝对路径/opencode-go-usage"]
}
```

四个典型错误：

| 错误 | 症状 | 修法 |
|---|---|---|
| 文件不存在 | 插件从未被加载 | 按 [安装指南](安装指南_20260916.md) 创建它 |
| 写进了 `opencode.json` / `opencode.jsonc` | 插件被 loader 拒绝 | `opencode.json` 只加载 **server 端**插件；CLI 插件必须在 `cli.json` 的 `plugins` 里。从 `opencode.json` 的 `plugins` 数组里删掉本插件，加到 `cli.json` |
| 路径指向 `tui.tsx` 文件 | 日志报 `configured plugin path must be a directory`，插件不加载 | V2 的 `plugins` 要写**插件目录**（仓库根目录），不能写文件。改成 `/绝对路径/opencode-go-usage` |
| 路径是相对路径或写错了 | 加载失败 | `plugins` 数组里必须是插件目录的**绝对路径**。用 `ls -ld` 确认那个目录真的存在，且里面有 `package.json` |

**确认路径真的指向目录：**

```bash
ls -ld "$(python3 -c "import json,pathlib;print(json.loads(pathlib.Path.home().joinpath('.config/opencode/cli.json').read_text())['plugins'][0])")"
```

**检查 opencode 版本：**

```bash
opencode --version
```

需要 **2.1.2 或更高**。V2 的 CLI 插件 API（`@opencode/plugin/tui`）在 2.1.2 上实测通过；更低版本可能没有 `Plugin.define` 或 `sidebar.content` slot。

**确认重启了：** `cli.json` 只在客户端启动时读取。改完必须完全退出再开，不是新建一个会话。

**还是定不下来？用探针插件。** 这是唯一能区分"loader 没加载"和"加载了但内部逻辑失败"的手段——插件内部的错误走 `console.error`，在 TUI 里会被吞掉，日志里什么都看不到。

装一个只写文件的最小插件（V2 要求目录形态，目录里用 `package.json` 的 `exports["./tui"]` 指向入口）：

```bash
mkdir -p /tmp/ocgo-probe
cat > /tmp/ocgo-probe/package.json <<'EOF'
{
  "name": "ocgo-probe",
  "type": "module",
  "exports": { "./tui": "./tui.tsx" }
}
EOF
cat > /tmp/ocgo-probe/tui.tsx <<'EOF'
/** @jsxImportSource @opentui/solid */
import { Plugin } from "@opencode/plugin/tui"
import { appendFileSync } from "node:fs"

const log = (m: string) => {
  try { appendFileSync("/tmp/ocgo-probe.log", `${new Date().toISOString()} ${m}\n`) } catch {}
}

export default Plugin.define({
  id: "ocgo-probe",
  setup(ctx) {
    log("setup() called")
    log(`app.version = ${ctx.app.version}`)
    try {
      const unregister = ctx.ui.slot({ append: "sidebar.content", render: () => null })
      log(`ui.slot returned: ${typeof unregister}`)
    } catch (e) {
      log(`ui.slot THREW: ${e instanceof Error ? e.message : String(e)}`)
    }
  },
})
EOF

# 临时加进 cli.json（先备份）
cp ~/.config/opencode/cli.json /tmp/cli.json.bak
python3 -c "
import json, pathlib
p = pathlib.Path.home()/'.config/opencode/cli.json'
cfg = json.loads(p.read_text())
if '/tmp/ocgo-probe' not in cfg['plugins']: cfg['plugins'].append('/tmp/ocgo-probe')
p.write_text(json.dumps(cfg, indent=2) + '\n')
"
rm -f /tmp/ocgo-probe.log
```

重启 opencode，然后：

```bash
cat /tmp/ocgo-probe.log
```

怎么读：

| 结果 | 结论 |
|---|---|
| 文件不存在 | **loader 根本没加载插件** — 回到上面查 `cli.json` 路径与 opencode 版本 |
| 有 `setup() called` 但没有 `ui.slot returned` | 注册抛错了，看那行 `THREW` 的消息 |
| 有 `ui.slot returned: function` | **加载与注册都正常**，问题在你自己插件的渲染逻辑或数据获取 |
| Plugins 对话框里能看到 `opencode-go-usage` 且 active | 本插件确实被加载了 |

V2 的 `ctx.location` / `ctx.app` 会给出宿主实际加载位置和版本，能直接看出插件在哪个目录运行、OpenCode 版本够不够。

用完恢复：

```bash
cp /tmp/cli.json.bak ~/.config/opencode/cli.json && rm -rf /tmp/ocgo-probe /tmp/ocgo-probe.log
```

### 1.2 没有密钥

诊断命令输出 `key: NOT FOUND` 时。

密钥按两级优先级解析（详见 [配置与行为契约 §3](配置与行为契约_20260916.md#3-密钥解析)）：

```bash
# 1. 环境变量优先
echo "${OPENCODE_GO_API_KEY:+已设置（值不打印）}"

# 2. 其次是 opencode 自己的 auth.json
python3 -c "
import json,pathlib
p = pathlib.Path.home()/'.local/share/opencode/auth.json'
d = json.loads(p.read_text())
print('providers:', list(d.keys()))
print('opencode-go 存在:', 'opencode-go' in d)
"
```

期望 `providers` 列表里有 `opencode-go`。

| 情况 | 修法 |
|---|---|
| `auth.json` 里没有 `opencode-go` | 跑 `opencode auth login` 登录 OpenCode Go，或设置环境变量 `OPENCODE_GO_API_KEY` |
| 键名被改过（比如测试时改成了 `opencode-go-bak`） | 改回 `opencode-go` |
| 密钥值是空字符串或纯空格 | 纯空白视为没有密钥。重新登录 |
| `auth.json` JSON 损坏 | 插件会静默退化为"没有密钥"。修复 JSON 或重新登录 |

改完**不需要重启** opencode：密钥在每次刷新时惰性解析，下一次 `session.idle` 或 5 分钟兜底刷新就会拾取。

### 1.3 无 Go 套餐或密钥失效

诊断命令输出 `snapshot.kind: dead` 时。看它打出的 `message`：

| message 含 | 含义 | 修法 |
|---|---|---|
| `subscription required` / `EntitlementError` | 这个密钥对应的账号**没有生效的 Go 套餐** | 确认套餐状态，或换一个有订阅的账号的密钥 |
| `HTTP 401` / `HTTP 403` | 密钥无效、已撤销、或无权访问 | 重新 `opencode auth login` 换新密钥 |

**`dead` 是闩锁。** 命中一次后插件永久停止请求，连 5 分钟兜底刷新也不再发。换好密钥后**必须重启 opencode** 才会恢复——这一点和 1.2 不同。

用 curl 直接确认（不经过插件）：

```bash
KEY=$(python3 -c "import json,pathlib;print(json.loads(pathlib.Path.home().joinpath('.local/share/opencode/auth.json').read_text())['opencode-go']['key'])")
curl -s -o /dev/null -w "HTTP %{http_code}\n" -H "authorization: Bearer $KEY" https://opencode.ai/zen/go/v1/usage
```

`HTTP 200` = 密钥和套餐都没问题。`HTTP 401`/`403` = 密钥问题。

> 别把密钥值贴进聊天、日志或 issue。上面的命令刻意只打状态码。

## 2. 小节位置

V2 的 `sidebar.content` 只支持 `append` / `prepend`，没有 `order`。本插件使用 `append`，固定出现在内置侧栏小节之后。这是 V2 插槽模型的限制，不能通过配置改变。

如果你希望额度出现在内置小节**之前**，只能修改 `tui.tsx` 里的 `append` 为 `prepend`；这不属于配置项，升级插件时会被覆盖。

## 3. 标题带感叹号

`OpenCode Go !` 意思是**上次刷新失败了，你看到的是上一次成功的数值**。这是刻意行为：额度是慢变量，显示 5 分钟前的值比闪成空白有用。

跑诊断命令看 `message`：

| message | 含义 | 修法 |
|---|---|---|
| 含 `ECONNRESET` / `fetch failed` / `ENOTFOUND` | 网络问题 | 检查网络、代理、DNS |
| 含 `aborted` / `AbortError` | 15 秒超时 | 网络慢或上游卡住。等下次刷新 |
| `HTTP 500` / `502` / `503` | 上游故障 | 等，会自己恢复 |
| `响应缺少 usage 字段` | 上游响应格式变了 | 上游改了 API。对照 [配置与行为契约 §1](配置与行为契约_20260916.md#1-数据源) 的结构核对 curl 返回 |

感叹号会在下一次成功刷新后自动消失（`session.idle` 或 5 分钟兜底）。不需要重启。

如果感叹号**一直不消失**且诊断命令正常，那是渲染层没收到更新，看 [§5](#5-数字永久不更新)。

## 4. 百分比没有右对齐

一行一档的布局靠 flex `gap={1}` 排版，各列宽度固定：标签 4 + 条 14 + 百分比 4 + 倒计时 6。

如果各列没有对齐（比如百分比或倒计时参差不齐），检查 `usage.ts` 的两个宽度常量与格式化函数是否被改过：

- `formatPercent` 必须恒返回 4 列（`padStart(4)`，打满时是 `" MAX"` 而不是中文「已达上限」——后者占 8 显示列会撑破排版）
- `formatCountdownShort` 必须恒 ≤ `COUNTDOWN_WIDTH`（6 列），渲染时再 `padStart(6)`
- 标签**不能**用 `padEnd` 对齐：中文字符 `length` 是 1 但显示占 2 列，`padEnd` 会按 `length` 补空格从而排错。三个标签都是 2 个中文字符（等宽 4 列），间距交给 flex `gap`

条子看不见（整行只有底色）时看下一条。

## 4.1 进度条看不见

条子是主题前景色细线，已用段用 `success`/`warning`/`error`，轨道段用主题的 `border`。

如果整条都看不见（或只看得见已用段、轨道完全融进背景），是主题把 `border` 设得和 `background` 太接近。代码里有运行时保护：`hasEnoughContrast(border, background)` 亮度差不足 0.12 时自动回退到 `text.muted`。如果回退后仍不可见，说明这个主题的 `text.muted` 也和背景太近，属于主题本身的问题。

**不要**把轨道改成更暗的背景层级（比如 `background.raised.base`）——它们的语义是「几乎不可见的表面」，做轨道等于没画。

## 5. 数字永久不更新

先确认它**真的**不更新：额度只在助手消耗配额后才变，5 小时窗口在你不用的时候本来就不动。发一条消息让助手回复完，等几秒再看。

如果确实卡住：

| 检查 | 命令 / 方法 | 含义 |
|---|---|---|
| 数据层是否还活着 | 跑诊断命令 | 正常 = 问题在插件内部状态 |
| 是否命中了 `dead` 闩锁 | 诊断命令返回 `dead` | 换密钥后必须**重启** |
| 倒计时分钟数是否在走 | 等 60 秒看 | 倒计时走但百分比不动 = 刷新没触发；两者都不动 = 渲染层冻结 |

刷新触发源有三个（详见 [配置与行为契约 §7](配置与行为契约_20260916.md#7-刷新触发)）：启动时一次、每次 `session.idle`（20 秒节流）、5 分钟兜底。所以**最长 5 分钟内必须有一次刷新**。超过 5 分钟百分比完全不动、且诊断命令正常 = 插件内部状态卡住，重启 opencode。

> 历史上有一条真实的永久冻结路径：15 秒超时原本只覆盖响应头，`response.json()` 无保护，body 挂住就会让单飞标志永久为真、此后所有刷新被挡死。已修（超时现在覆盖到 body 读取完成）。如果你在 `6f0faf5` 之前的版本上，升级。

## 6. 百分比和 web dashboard 不一致

**这不是 bug。** opencode 官方 web dashboard 显示一位小数（`8.1%` / `53.4%` / `26.7%`），插件显示整数（`8%` / `53%` / `27%`）。

`/zen/go/v1/usage` 这个端点返回的 `percent` 就是**向下取整的整数**，web dashboard 走的是另一条更精细的通路。插件取不到小数位，这是数据源的硬限制，不是渲染问题。

同理，端点不返回 token 数或金额绝对值，所以插件做不了"还剩多少 token"。

验证：

```bash
KEY=$(python3 -c "import json,pathlib;print(json.loads(pathlib.Path.home().joinpath('.local/share/opencode/auth.json').read_text())['opencode-go']['key'])")
curl -s -H "authorization: Bearer $KEY" https://opencode.ai/zen/go/v1/usage | python3 -m json.tool
```

返回里的 `percent` 都是整数。

## 7. 倒计时显示"重置时间未知"

说明 `resetsAt` 不是可解析的时间串。上游返回格式变了。

```bash
KEY=$(python3 -c "import json,pathlib;print(json.loads(pathlib.Path.home().joinpath('.local/share/opencode/auth.json').read_text())['opencode-go']['key'])")
curl -s -H "authorization: Bearer $KEY" https://opencode.ai/zen/go/v1/usage | python3 -c "
import json,sys
for k,v in json.load(sys.stdin)['usage'].items():
    print(k, repr(v.get('resetsAt')))
"
```

期望是 ISO 8601 串，如 `'2026-09-21T00:00:00.724Z'`。

如果看到 `即将重置` 而不是"未知"，那是 `resetsAt` 已经过期（差值 ≤ 0），会在上游下次返回新时刻后自动恢复，不是故障。

## 7.1 改了配置没生效

配置走 `cli.json` 的对象形式：

```jsonc
"plugins": [
  {
    "package": "/绝对路径/opencode-go-usage",
    "options": { "style": "detailed" }
  }
]
```

| 症状 | 原因 | 修法 |
|---|---|---|
| 完全没变化 | `cli.json` 只在客户端启动时读 | 完整退出 opencode 再开，新建会话不算 |
| 样式没变，仍是 compact | `style` 值写错（大小写敏感，只认 `"compact"` / `"detailed"` / `"ledger"`） | 非法值会**静默回退**到默认而不报错。核对拼写 |
| 插件整个消失 | 对象形式写错了（比如漏了 `package` 或 `options` 不是对象） | 每一项要么是字符串，要么是 `{ "package": "路径", "options": { ... } }` |

三种布局的实际截图、持久配置和当前会话命令见[样式切换指南](OpenCodeGo样式切换指南_20260917.md)。

配置解析是"任何形状都不抛错"的设计——好处是手写 JSON 出错不会让插件加载失败，代价是**写错了没有提示**。改完拿不准就对照 README 的配置表逐字核一遍。

## 8. `bun install` 或 `tsc` 失败

**`bun` 没装：**

```bash
bun --version
```

需要 bun（本项目在 1.3.14 上验证）。装它：`curl -fsSL https://bun.sh/install | bash`。

**`tsc` 报 `<box>` / `<text>` 的 JSX 元素隐式 any：**

说明 `@opentui/core` 的 JSX 命名空间没被加载。在 `tsconfig.json` 的 `compilerOptions.types` 里补上 `"@opentui/core"`：

```jsonc
{
  "compilerOptions": {
    "types": ["bun", "@opentui/core"]
  }
}
```

**依赖装了但运行时报找不到模块：**

V2 由 OpenCode 解析 `@opencode/plugin/tui`、`@opentui/*` 与 `solid-js` 到宿主自己的运行时；本地 `node_modules` 纯粹是给 `tsc` 与 `bun test` 用的。这也顺带排除了"两份 Solid 导致响应式失联"的隐患。

**测试失败：**

```bash
bun test
```

期望 76 pass / 0 fail。如果有失败，对照 [配置与行为契约 §10](配置与行为契约_20260916.md#10-测试覆盖) 的覆盖表定位是哪一块。

## 完全卸载

从 `~/.config/opencode/cli.json` 的 `plugins` 数组里删掉指向本仓库 `tui.tsx` 的那一项。如果 `plugins` 里只有这一项，可以直接删掉整个文件：

```bash
python3 - <<'EOF'
import json, pathlib
p = pathlib.Path.home() / ".config/opencode/cli.json"
cfg = json.loads(p.read_text())
cfg["plugins"] = [x for x in cfg.get("plugins", []) if "opencode-go-usage" not in str(x)]
p.write_text(json.dumps(cfg, indent=2, ensure_ascii=False) + "\n")
EOF
```

重启 opencode。你原有的 `opencode.json` / `opencode.jsonc` 从未被本插件改动过。

如果 `cli.json` 里还注册了别的 CLI 插件，只从 `plugins` 数组里删掉本插件那一项，别删整个文件。
