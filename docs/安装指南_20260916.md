# 安装指南 — Tutorial

**日期：** 2026-09-16

走完这份文档你会在 opencode 的侧栏里看到这个，紧跟在 `Context` / `MCP` / `LSP` 下面：

```
OpenCode Go
滚动  █░░░░░░░░░░░░░   8%   4h58m
本周  ████████░░░░░░  55%   4d10h
本月  ████░░░░░░░░░░  27%  27d16h
```

一行一档，三步，重启一次 opencode 就能看见。全程用 `$REPO` 变量，不含任何硬编码路径，所以换机器或给别人用都能直接照做。

## 需要什么

| 项 | 要求 | 怎么确认 |
|---|---|---|
| opencode | **≥ 1.18.30** | `opencode --version` |
| bun | 任意近期版本（本项目在 1.3.14 上验证） | `bun --version`，没有就 `curl -fsSL https://bun.sh/install \| bash` |
| OpenCode Go 套餐 | 账号要有生效的订阅 | 下面 Step 3 会验证 |
| 密钥 | opencode 里已登录过 OpenCode Go | `opencode auth login`，或设环境变量 `OPENCODE_GO_API_KEY` |

opencode 版本是硬要求。这套 TUI 插件 API 没有公开文档，已在 1.18.30 与 1.18.31 上实测通过；更低版本可能根本没有 `sidebar_content` slot。

> 如果你就是在这个仓库的原始机器上（`~/workspace/opencode-go-usage`），插件已经装好了，跳到 [Step 3](#step-3-重启-opencode) 直接看效果。

## Step 1: 拿到代码，装依赖

```bash
export REPO="$HOME/workspace/opencode-go-usage"
git clone <仓库地址> "$REPO" 2>/dev/null || echo "已存在，跳过 clone"
cd "$REPO" && bun install
```

`$REPO` 后面每一步都会用到，所以别换终端窗口（换了就重新 `export` 一次）。

装完确认一下逻辑层是好的：

```bash
bun test
```

期望 `64 pass` / `0 fail`。

> 这里装的 `@opentui/*` 和 `solid-js` 只给 TypeScript 类型检查用。运行时 opencode 会把这些 import 解析到它自己内置的 Solid 运行时，所以不存在"两份 Solid"的问题。

---

## Step 2: 注册插件

TUI 插件注册在 `~/.config/opencode/tui.json`。**不是** `opencode.json`——后者只加载 server 端插件，TUI 插件写进去会被 loader 拒绝。

下面这条命令会创建该文件，或者在它已存在时把本插件**追加**进去（保留你原有的 `theme`、keybinds 和其他插件），重复跑也不会写重复项：

```bash
TUI_JSON="$HOME/.config/opencode/tui.json" REPO="$REPO" python3 -c '
import json, os, pathlib
p = pathlib.Path(os.environ["TUI_JSON"]); repo = os.environ["REPO"]
entry = f"{repo}/tui.tsx"
p.parent.mkdir(parents=True, exist_ok=True)
cfg = json.loads(p.read_text()) if p.exists() else {"$schema": "https://opencode.ai/tui.json"}
plugins = cfg.setdefault("plugin", [])
if entry not in plugins: plugins.append(entry)
p.write_text(json.dumps(cfg, indent=2, ensure_ascii=False) + "\n")
print("已写入:", p)
'
```

看一眼结果：

```bash
cat ~/.config/opencode/tui.json
```

全新安装时应该是：

```json
{
  "$schema": "https://opencode.ai/tui.json",
  "plugin": [
    "/Users/你/workspace/opencode-go-usage/tui.tsx"
  ]
}
```

`plugin` 里必须是**绝对路径**，相对路径不会被解析。

> 不想用命令的话手写这个文件也行，内容就是上面那样。

想换样式或调位置，把那一项从字符串改成 `[路径, 配置]`：

```jsonc
"plugin": [
  ["/绝对路径/opencode-go-usage/tui.tsx", { "style": "detailed", "order": 600 }]
]
```

两种样式与全部字段见 [README 的配置节](../README.md#配置)。

## Step 3: 重启 opencode

`tui.json` 只在启动时读取，所以要完整退出再开，新建会话不算。

```bash
opencode
```

进任意会话，看侧栏。`Context` / `MCP` / `LSP` 下面应该出现 `OpenCode Go` 小节和三档额度。

**看到了** → 跳到下面的[确认它在工作](#确认它真的在工作)。

**没看到** → 这是预期内的常见情况，因为插件有四条静默失败路径（没密钥、没套餐、密钥失效、插件没加载），全都表现成"整节不显示"。跑这一条就能定位：

```bash
cat > /tmp/ocgo-diag.ts <<'EOF'
const repo = process.env.REPO
if (!repo) { console.error("请先 export REPO=<仓库绝对路径>"); process.exit(2) }
const { defaultStateDir, resolveKey, fetchUsage } = await import(`${repo}/usage.ts`)
const dir = defaultStateDir()
const key = resolveKey(dir)
console.log("stateDir:", dir)
console.log("key:", key ? `found (len=${key.length})` : "NOT FOUND")
if (key) {
  const snap = await fetchUsage(key)
  console.log("snapshot.kind:", snap.kind)
  if (snap.kind !== "ok") console.log("message:", snap.message)
}
EOF

bun run /tmp/ocgo-diag.ts
```

| 输出 | 意思 | 去哪 |
|---|---|---|
| `key: NOT FOUND` | 密钥没解析到 | 跑 `opencode auth login` 登录 OpenCode Go |
| `snapshot.kind: dead` | 没有 Go 套餐，或密钥失效 | 看 `message`；换密钥后**必须重启** |
| `snapshot.kind: soft-error` | 网络或上游问题 | 看 `message`，通常等一下自己好 |
| `snapshot.kind: ok` | **数据层完好，是插件没被加载** | 回 Step 2 检查 `tui.json` 路径对不对、有没有误写进 `opencode.json`、opencode 版本够不够 |

完整的症状对照表在 [排障指南](排障指南_20260916.md)。

## 确认它真的在工作

看到数字不代表刷新链路是活的——它可能只渲染了启动那一次。做两件事：

**1. 核对数字是真的。** 跑上面那条诊断命令（完整版在[排障指南](排障指南_20260916.md#先跑这一条数据层诊断)），比对它打出的百分比和侧栏显示的一致。

**2. 看它会更新。** 在会话里发一条消息，等助手回复完。回复结束后几秒内百分比应该会变（由 `session.idle` 事件驱动，20 秒内不重复请求）。

如果只有倒计时的分钟数在走、百分比一直不动，那是刷新没触发，看 [排障指南 §5](排障指南_20260916.md#5-数字永久不更新)。

---

## 你得到了什么

侧栏里一个常驻的额度面板，它会：

- 在助手每次回复结束后刷新（20 秒节流），另有 5 分钟兜底定时刷新；
- 倒计时每 60 秒本地重算，不发多余请求；
- 上游出问题时**保留上次数值**并在标题打个 `!`，而不是闪成空白；
- 没有密钥、没有套餐、或密钥失效时**整节消失**，不占行、不报错。

密钥直接复用 opencode 自己 `auth.json` 里的 `opencode-go.key`，插件不存任何副本、不打印、不落盘。

## 卸载

```bash
rm ~/.config/opencode/tui.json
```

重启 opencode。如果那个文件里还有别的 TUI 插件，只从 `plugin` 数组里删掉本插件那一项。你的 `opencode.json` / `opencode.jsonc` 从未被本插件改动。
