# 配置与行为契约 — Reference

**日期：** 2026-09-16 · **对应代码：** `usage.ts` / `tui.tsx`

这份文档是插件全部可观察行为的完整清单：数据源、密钥解析顺序、时间常量、侧栏排序、渲染格式、失败矩阵。每一项都标了**符号名**而不是行号——行号一改代码就失效且没人会发现，符号名 `grep` 一次就能定位。改代码时同步改这里。

需要"为什么这样设计"看 [设计规格](superpowers/specs/OpenCodeGo额度侧栏_20260916.md)；需要"装不上/看不到"看 [排障指南](排障指南_20260916.md)。

## 1. 数据源

```
GET https://opencode.ai/zen/go/v1/usage
Authorization: Bearer <OpenCode Go API Key>
Accept: application/json
```

| 项 | 值 | 位置 |
|---|---|---|
| 基地址 | `https://opencode.ai` | `usage.ts` `DEFAULT_BASE_URL` |
| 路径 | `/zen/go/v1/usage` | `usage.ts` `USAGE_PATH` |
| 方法 | `GET` | `usage.ts` `fetchUsage` |

尾部斜杠会被去掉（`baseUrl.replace(/\/$/, "")`），所以 `https://opencode.ai/` 与不带斜杠等价。

这是一个**未公开**端点，opencode 官方文档没有它。响应结构：

```json
{"usage":{
  "rolling": {"status":"ok","percent":8, "resetsAt":"2026-09-16T08:22:31.724Z"},
  "weekly":  {"status":"ok","percent":53,"resetsAt":"2026-09-21T00:00:00.724Z"},
  "monthly": {"status":"ok","percent":26,"resetsAt":"2026-10-14T07:37:52.724Z"}
}}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `rolling` | `UsageWindow` | 5 小时滚动窗口 |
| `weekly` | `UsageWindow` | 自然周 |
| `monthly` | `UsageWindow` | 计费月 |
| `.status` | `string` | `"ok"` 或 `"rate-limited"`（该窗口已打满） |
| `.percent` | `number` | 已用百分比，**只有整数精度** |
| `.resetsAt` | `string` | ISO 8601 重置时刻 |

三个 `resetsAt` 的毫秒部分相同，服务端由同一个 `now` 加不同偏移算出。

**精度限制：** `percent` 是向下取整的整数。opencode 官方 web dashboard 同一时刻显示一位小数（如 `8.1%` / `53.4%` / `26.7%`），走的是另一条更精细的通路，本端点取不到。端点也不返回 token 数或金额绝对值，所以 UI 的上限就是"整数百分比 + 进度条 + 重置倒计时"。

响应会过运行时结构校验（`isUsage` / `isUsageWindow`）：三个窗口都必须存在，且 `status` 是字符串、`percent` 是数字、`resetsAt` 是字符串。任一不满足则降级为 `soft-error`。

## 2. 密钥解析

按顺序取第一个非空白值，插件不保存任何副本：

| 优先级 | 来源 | 位置 |
|---|---|---|
| 1 | 环境变量 `OPENCODE_GO_API_KEY` | `usage.ts` `ENV_KEY` |
| 2 | `<stateDir>/auth.json` 的 `opencode-go.key` | `usage.ts` `AUTH_PROVIDER` |

两处都做 `.trim()`，纯空白视为没有密钥。`auth.json` 缺失、无读权限、JSON 损坏、顶层不是对象，全部退化为"没有密钥"，不抛错。

`auth.json` 在 opencode 的 **data** 目录，不是 state 目录。这两个是 XDG 规范里不同的位置，实测值：

| opencode 提供的路径 | 实际值（macOS） | 里面有什么 |
|---|---|---|
| **data** 目录 = `defaultStateDir()` 算出的值 | `~/.local/share/opencode` | **`auth.json`**、`log`、`opencode.db` |
| `api.state.path.state`（**state** 目录） | `~/.local/state/opencode` | `kv.json`、`locks`、`model.json`、`plugin-meta.json` |

所以 `resolveKey` 接受**候选目录列表**，按顺序找第一个能读到 `opencode-go.key` 的：

1. `defaultStateDir()` —— data 目录，`auth.json` 的真实位置
2. `api.state?.path?.state` —— state 目录，留作次选（防某些安装两者一致或宿主日后改动）

单个候选目录读不到（文件缺失、无权限、JSON 损坏、缺 `opencode-go` 键）时继续试下一个，全部试完才返回 `null`。

`defaultStateDir()` 算的是 **data** 目录：

| 平台 | 值 |
|---|---|
| macOS / Linux | `$XDG_DATA_HOME/opencode`，未设则 `~/.local/share/opencode` |
| Windows | `%LOCALAPPDATA%\opencode`，未设则 `~\AppData\Local\opencode` |

> 早期版本写的是 `api.state.path.state || defaultStateDir()`，把两个目录当成了同一个。由于 `api.state.path.state` 永远非空，回退分支永远不触发，密钥永远找不到，整节永不渲染。41 个单测全绿也没抓到——测试用的是临时目录加注入的 env，从未验证过"宿主给的 state 目录是否就是 auth.json 所在目录"。

密钥在**每次刷新时惰性解析**，所以会话中途新增密钥也会被拾取，不必重启。

密钥只出现在局部变量与 `authorization` 请求头里。不进日志、不进 `kv`、不进任何错误消息、不落盘。

## 3. 时间常量

| 常量 | 值 | 作用 | 位置 |
|---|---|---|---|
| `TIMEOUT_MS` | 15 秒 | 单次请求超时，**覆盖到 body 读取完成** | `usage.ts` `TIMEOUT_MS` |
| `THROTTLE_MS` | 20 秒 | 两次上游请求的最小间隔 | `usage.ts` `THROTTLE_MS` |
| `FALLBACK_MS` | 5 分钟 | 兜底定时刷新（`force`，绕过节流） | `tui.tsx` `FALLBACK_MS` |
| `TICK_MS` | 60 秒 | 倒计时文本本地重算间隔，**不发请求** | `tui.tsx` `TICK_MS` |

关于超时边界：15 秒的 `AbortController` 覆盖 fetch **和** `response.json()` 两段。这一点是刻意的——只覆盖响应头会留下一条"服务端发了头不发完 body"的永久卡死路径。

关于节流起算点：`lastAt` 在 `await` **之前**打戳，所以 20 秒窗口从**请求发起**时刻起算，不是从完成时刻。一个耗时 3 秒的请求之后，下次可刷新时刻是 20 秒后而非 23 秒后。

`throttleMs` 可通过 `createRefresher({ throttleMs })` 注入（测试用假时钟时需要）。生产接线不传，取默认 20 秒。

## 4. 侧栏排序契约

插件注册到 `sidebar_content` slot，`order: 350`（见 `tui.tsx` 的 `api.slots.register` 调用）。

`sidebar_content` 是**叠加模式**，多个插件共存，按 `order` 升序排列。`@opentui/core` 的 `SlotRegistry.getSortedPlugins()` 排序规则：`order` 升序 → 注册顺序 → `id.localeCompare`。

从 opencode 1.18.30 二进制解出的内置 order 表：

| 插件 id | order |
|---|---|
| `internal:sidebar-context` | 100 |
| `internal:sidebar-mcp` | 200 |
| `internal:sidebar-lsp` | 300 |
| `internal:sidebar-todo` | 400 |
| `internal:sidebar-files` | 500 |

`350` 落在 `lsp`(300) 与 `todo`(400) 之间，即"紧随 Context / MCP / LSP 之后"。

**这是与宿主的隐式契约。** 宿主升级调整内置 order 时要同步复核。外部插件在 TUI 启动后加载，所以与内置插件同档时会排在它之后——这正是最初写 `order: 100` 的 bug：它与 `internal:sidebar-context` 同档，结果落在 Context 之后、**MCP 之前**。

想让额度沉到侧栏最底（排在 Todo / Files 之下）：把 `order` 改成 `600`。

其他与宿主的契约项：

| 项 | 值 | 为什么 |
|---|---|---|
| 注册文件 | `~/.config/opencode/tui.json` | `opencode.json` 只加载 server 端插件，TUI 插件放进去会被 loader 拒绝 |
| 模块导出 | `export default { id, tui }` | 同时导出 `server` 会被拒 |
| 插件 id | `opencode-go-usage` | `tui.tsx` 末尾的 `export default` |
| JSX 运行时 | 首行 `/** @jsxImportSource @opentui/solid */` | opencode 二进制自带 solid JSX 变换 |
| slot 渲染器签名 | `(ctx) => JSX.Element` | 真实类型是 `(ctx, props) => TNode`；少声明尾参是合法结构化子类型，宿主自己的 `internal:sidebar-lsp` 连 `ctx` 都不声明 |

## 5. 渲染规格

```
OpenCode Go
5 小时用量             8%
██░░░░░░░░░░░░░░░░░░
重置于 31 分钟
每周用量              53%
███████████░░░░░░░░░
重置于 4 天 16 小时
每月用量              27%
█████░░░░░░░░░░░░░░░
重置于 27 天 23 小时
```

### 节标题

`OpenCode Go`，`stale` 时变为 `OpenCode Go !`（见 `tui.tsx` 的 `sidebar_content` 渲染体）。用 `theme.current.textMuted`，与宿主的 `Context` / `MCP` / `LSP` 小节同构。

### 窗口顺序与标签

`usage.ts` 的 `ROWS`：

| key | 标签 |
|---|---|
| `rolling` | `5 小时用量` |
| `weekly` | `每周用量` |
| `monthly` | `每月用量` |

### 进度条

`formatBar(percent, width = BAR_WIDTH)`，`BAR_WIDTH = 20`（`usage.ts`）。

已用格数 = `Math.round(percent / 100 * width)`，字符 `█`（已用）/ `░`（剩余）。输入被夹到 0-100，非有限值按 0 处理，总宽恒为 20。

| percent | 已用格数 |
|---|---|
| 0 | 0 |
| 8 | 2 |
| 26 | 5 |
| 53 | 11 |
| 100 | 20 |

`█`(U+2588) 与 `░`(U+2591) 是 East Asian Ambiguous 宽度字符。opencode 走 `unicode` 宽度模式（不是 `unicode-wide`），Ambiguous 按 1 列算，所以 20 格条占 20 列。侧栏内容区约 37 列，宽裕。

### 百分比

`formatPercent(percent, status)`：

| 条件 | 输出 |
|---|---|
| `status === "rate-limited"` | `已达上限` |
| 其他 | `${Math.round(percent)}%` 右对齐到 4 字符 |

右对齐在 flex 布局下由 `<box flexGrow={1} />` 弹性间隔实现，`padStart(4)` 的空格落在数字左侧被间隔吸收。

### 倒计时

`formatCountdown(resetsAt, now = Date.now())`。先把毫秒差折算成总分钟再拆分，避免秒级抖动导致文本反复变化。

| 条件 | 输出 |
|---|---|
| 时间串无法解析 | `重置时间未知` |
| 已过期（差值 ≤ 0） | `即将重置` |
| ≥ 1 天 | `重置于 N 天 M 小时` |
| ≥ 1 小时 | `重置于 N 小时 M 分钟` |
| 其他 | `重置于 M 分钟` |

### 色调

`toneOf(percent, status)` 返回色调**名**，由 `tui.tsx` 的 `toneColor` 映射到主题色：

| 条件 | 色调名 | 主题色 |
|---|---|---|
| `status === "rate-limited"` 或 `percent >= 90` | `danger` | `theme.current.error` |
| `percent >= 70` | `warn` | `theme.current.warning` |
| 其他 | `ok` | `theme.current.success` |

阈值边界：69 → `ok`，70 → `warn`，89 → `warn`，90 → `danger`。

标签、百分比、倒计时一律用 `textMuted`；只有进度条本身带色调。

主题切换（`/theme`）会实时跟随：`theme` 作为 `TuiTheme` 对象往下传，`.current` 在每个 JSX 调用点分别解引用。

## 6. 刷新触发

| 触发源 | force | 说明 |
|---|---|---|
| 插件启动 | ✅ | 绕过节流，立即拉一次 |
| `session.idle` 事件 | ❌ | 助手每次回复结束时触发，受 20 秒节流约束 |
| 兜底 interval（5 分钟） | ✅ | 绕过节流，覆盖"额度在别处被消耗" |
| 倒计时 tick（60 秒） | — | 只重算文本，**不发请求** |

`session.idle` 在子 agent 场景下可能密集触发，20 秒节流是为此设的下限。

同一时刻只允许一个请求在飞（`inflight` 单飞标志）。插件卸载时（`api.lifecycle.onDispose`）注销事件订阅并清除两个 interval。

## 7. 失败矩阵

`fetchUsage` 把每种结果归为三态 `Snapshot`（`usage.ts` 的 `Snapshot` 类型）：

| 上游情况 | Snapshot | UI 行为 | 后续 |
|---|---|---|---|
| 正常 | `ok` | 渲染三档额度 | 继续刷新 |
| `error.type === "EntitlementError"`（无 Go 套餐） | `dead` | **整节不渲染** | **永久停止请求** |
| HTTP 401 / 403 | `dead` | **整节不渲染** | **永久停止请求** |
| 网络错误 / 超时 | `soft-error` | 保留上次数值，标题 `OpenCode Go !` | 下次触发再试 |
| HTTP 5xx 及其他非 2xx | `soft-error` | 同上 | 下次触发再试 |
| 响应缺 `usage` 或字段类型不对 | `soft-error` | 同上 | 下次触发再试 |
| 没有密钥 | —（不发请求） | **整节不渲染** | 每次刷新重试解析 |

`EntitlementError` 的判断排在状态码之前，因为该错误伴随 403 返回——先判状态码会丢掉上游给的具体原因。

`dead` 是**闩锁**：命中一次后 `refresh` 永久短路，连 `force` 也不再发请求。恢复需要重启 opencode。

`soft-error` **不清空**上次快照。额度是慢变量，显示 5 分钟前的值远好于闪成空白。

四条"整节不渲染"的路径合起来意味着：**看不到额度小节是正常行为，不是崩溃。** 诊断见 [排障指南](排障指南_20260916.md)。

## 8. 公共 API 表面

`usage.ts` 的 19 个导出。唯一的消费者是 `tui.tsx`；列在这里是为了维护时不必通读源码。

### 类型

| 名称 | 形状 |
|---|---|
| `UsageWindow` | `{ status: string; percent: number; resetsAt: string }` |
| `Usage` | `{ rolling: UsageWindow; weekly: UsageWindow; monthly: UsageWindow }` |
| `Snapshot` | `{kind:"ok";usage:Usage}` \| `{kind:"soft-error";message:string}` \| `{kind:"dead";message:string}` |
| `Tone` | `"ok" \| "warn" \| "danger"` |
| `RefresherDeps` | `createRefresher` 的注入依赖，见下 |
| `Refresher` | `{ refresh: (force: boolean) => Promise<void> }` |

### 常量

| 名称 | 值 |
|---|---|
| `ENV_KEY` | `"OPENCODE_GO_API_KEY"` |
| `AUTH_PROVIDER` | `"opencode-go"` |
| `DEFAULT_BASE_URL` | `"https://opencode.ai"` |
| `BAR_WIDTH` | `20` |
| `ROWS` | 三个 `{ key, label }`，见 §5 |

### 函数

| 签名 | 作用 |
|---|---|
| `defaultStateDir(env?, platform?, home?): string` | 平台默认 **data** 目录（auth.json 所在处） |
| `resolveKey(stateDir \| stateDirs[], env?): string \| null` | 按 §2 优先级解析密钥，接受单个目录或候选列表 |
| `fetchUsage(key, baseUrl?, fetchImpl?, timeoutMs?): Promise<Snapshot>` | 拉一次额度，归为三态 |
| `createRefresher(deps): Refresher` | 刷新状态机工厂，见下 |
| `formatBar(percent, width?): string` | 20 格进度条 |
| `toneOf(percent, status): Tone` | 色调名 |
| `formatPercent(percent, status): string` | 右对齐百分比文本 |
| `formatCountdown(resetsAt, now?): string` | 中文倒计时 |

`fetchUsage` 的后三个参数都是注入点（基地址、`fetch` 实现、超时），前三个的顺序与含义在改动时要保持稳定。

### `createRefresher` 的依赖

```ts
type RefresherDeps = {
  resolveKey: () => string | null
  fetchUsage: (key: string) => Promise<Snapshot>
  now: () => number
  onUsage: (usage: Usage) => void
  onDead: () => void
  onStale: (stale: boolean) => void
  throttleMs?: number
}
```

时钟与 IO 全部注入，所以这套状态机能用假时钟测试而不必起 TUI。`dead` 与 `inflight` 是工厂内部闭包状态，不对外暴露。

`refresh` 整体包了 try/catch 兜底：吞掉一切异常且不打印，避免 TUI 进程出现未处理 rejection 污染渲染画面。
